Arc Delivery Receipts

Circle Gateway nanopayments batch settlement, so a buyer gets no per-payment receipt on chain. This page restores one for purchases on Arc: each signed Gateway authorization is checked against Circle Gateway’s record: a batch settlement and the buyer’s balance change or, for a seller that declares a prepaid balance, settled top-ups that cover the call. A Merkle root of what each seller returned is recorded on Arc before anything is published.

Follow one purchase end to end

  1. Signed authorization (EIP-712, GatewayWalletBatched on Arc): nonce 0xb973c86a716d0253aef8a33f504f4c13097722ceca40e428d517994ebcb5eb5b, 0.1 USDC to 0xBd7b9f3e0CD3E1f6e698D0eeBb99F96E093BdeE3.
  2. Circle Gateway maps the nonce to its batch: Gateway API.
  3. It settled in batch tx 0x6ae70bf1ac146895…; in that tx the buyer’s Gateway balance fell by exactly the sum of its charged authorizations (checked by verify.mjs from Arc RPC).
  4. What came back: HTTP 200, 24 bytes, application/json; charset=utf-8, sha256 0xd4a387cd5cc32e213f66c4a9493bef39bdf8f9be0226dec60c534d68f0ee0606.
  5. That record is leaf 0x23ce49fe5d8d2d563c8d298206ddf97dd2ea678f0a8d374eb03c7c6bffcc3d3c; its Merkle proof leads to the root stored in DeliveryLedger round 3.

Check a seller before paying

// GET https://kzmttkc.github.io/arc-delivery-receipts/api/v1/arc/sellers/<payTo>.json  →  { deliveryRate, purchases, lastChecked, evidence[] }
client.onBeforePaymentCreation(async (ctx) => {
  const payTo = ctx.selectedRequirements.payTo.toLowerCase();
  const r = await fetch(`https://kzmttkc.github.io/arc-delivery-receipts/api/v1/arc/sellers/${payTo}.json`);
  if (!r.ok) return;                                  // never checked: your call
  const s = await r.json();
  if (s.purchases >= 3 && s.deliveryRate < 0.8) {
    return { abort: true, reason: `delivery rate ${s.deliveryRate} over ${s.purchases} paid calls` };
  }
});

The same per-seller history is the kind of data an agent-transaction insurer would need to price a policy.

Verify it yourself

git clone https://github.com/kzmttkc/arc-delivery-receipts && cd arc-delivery-receipts && npm ci
node verify.mjs public/rounds/3/records.json

What it proves and what it does not: it proves which authorizations the buyer signed, that Circle settled them in batches that debited the buyer by exactly those amounts, and which bytes each seller returned, fixed on Arc before publication. Seller-side credits are netted with other buyers in the same batch, so they can be checked only in aggregate. A “delivered” result says the response passed four published checks, not that its content was useful.
